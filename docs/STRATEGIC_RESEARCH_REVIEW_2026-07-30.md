# Strategic Research Review

**Date:** 2026-07-30  
**Authority:** Research Director (implementation **suspended**)  
**Question:** Are we climbing the right mountain?  
**End goal:** A **trustworthy autonomous trading system** that can **eventually manage real capital** — not “another backtest,” not “busy science,” not “architecture for its own sake.”  
**Method:** Work **backwards** from capital-ready autonomy; challenge major assumptions; multi-role debate; consensus roadmap.  
**Status:** **Design only.** Do not implement this roadmap until the human accepts a path.

---

## 0. One-line answer

**We have been climbing a real mountain, but often the wrong face.**  
Phase 1 proved that **free-shelf daily BTC long/flat signal discovery** is a low-probability route to capital-ready autonomy. The lab’s **rejection engine and operating system** are high-value assets; the **alpha path** that maximises P(eventual real-capital system) is **not** “more free programmes” and **not** “options data by default as Phase 2 copy-paste.”  

**Consensus:** Re-frame the goal as a **capital-ready system stack** (edge + risk + execution + monitoring + kill-switch), pursue **one structural information test** *or* **mandate-aligned market-structure edges**, and treat **productising the research OS** as a parallel value path if alpha remains scarce.

## 1. Work backwards from the end state

### 1.1 What “trustworthy autonomous trading system managing real capital” requires

Not one thing. A **stack**:

| Layer | Must be true |
|-------|----------------|
| **L0 Governance** | Written risk limits, kill-switch, human override, no silent leverage, audit trail |
| **L1 Capital safety** | Position sizing, drawdown stops, venue risk, operational security, legal/tax fit |
| **L2 Execution** | Reliable order path, costs model ≈ reality, latency/lag honest, reconciliation |
| **L3 Monitoring** | Live drift detection, data feed health, strategy health, alerting |
| **L4 Validation** | Pre-reg, frozen gates, confirmatory, shadow, then tiny capital — **not** full-sample glory |
| **L5 Edge** | Economic mechanism + reproducible advantage **after** costs under the chosen mandate |
| **L6 Scale** | Capacity, multi-account or multi-strategy only after L0–L5 hold |

**Critical insight:** Phase 1 optimised almost entirely for **L5 under a narrow mandate**, while **L0–L4** are largely built. That is asymmetric: we built a mountain railway to a summit that may not have ore under **that** claim.

### 1.2 Dependency graph (backward)

```text
Real capital autonomy
  ← shadow survival + ops readiness
    ← confirmatory survivor under frozen gates
      ← pre-reg programme on admissible PIT data
        ← mandate definition (what may be traded)
          ← economic mechanism class with non-zero prior
            ← lab that can reject false edges (already strong)
```

**Bottleneck today:** not code. **Mandate × information class × edge prior.**

### 1.3 Phase 1 evidence (constraints, not religion)

| Result | Implication |
|--------|-------------|
| Mass free OHLCV technical nulls; PCS rejections | Low prior on public daily long/flat technicals |
| ETF / stablecoin-growth / miner free structural nulls | Low prior on **easy free** structural long/flat |
| Research OS + gates mature | High prior that **we can trust nulls and survivors** |
| Conclusion B issued | Residual option value in **richer data or mandate change**, not free fillers |

## 2. Challenge every major assumption

### A1 — “The goal is to discover a standalone BTC long/flat strategy”

| Challenge | Working resolution |
|-----------|-------------------|
| Real capital systems are often **portfolios**, risk overlays, or **market-structure** books (basis, funding), not single daily long/flat rules. | **Standalone long/flat BTC remains a valid *subset* goal**, not the only mountain. End goal should be stated as **capital-ready system under an explicit mandate**, of which long/flat spot is Mandate A. |
| “Standalone” encourages overfit single-rule heroics. | Prefer **small families with economic locks** + risk layer. |

### A2 — “BTC-only (or BTC-first) is optimal”

| Challenge | Working resolution |
|-----------|-------------------|
| BTC is most efficient crypto; edges may be thinner. ETH/alts may have slower diffusion **or** worse data/capacity. Multi-asset needs universe governance (already partially built). | Keep **BTC as primary evidence asset**. Allow **ETH only as secondary confirmatory / capacity check** after a BTC survivor — not as a way to escape BTC nulls with the same idea. Non-crypto (equities) is a **different product** (research OS generalisation), not Phase-next trading default. |

### A3 — “Alpha discovery should stay the sole primary objective”

| Challenge | Working resolution |
|-----------|-------------------|
| Lab already has commercial value as **rejection / evidence OS** even if alpha posterior stays low. | Run **dual objective** with **hard accounting separation**: Track α (science toward capital) vs Track Π (productise OS). Never spend confirmatory budget on Π. |

### A4 — “Next step is paid options OI/gamma (Phase 2 design)”

| Challenge | Working resolution |
|-----------|-------------------|
| Options path has moderate prior for **mechanism**, lower prior for **long/flat deployable** edge. Proxy stack (OI→dealer→hedge→spot) is fragile. | Options remains **top structural test under Mandate A**, not sacred. If human prefers mandate expansion, **funding/basis book** may dominate options for P(edge). |
| Blindly implementing prior Phase 2 design would ignore this review. | **Ignore prior roadmap where it conflicts** with backward reasoning (§0). |

### A5 — “No leverage / no short forever”

| Challenge | Working resolution |
|-----------|-------------------|
| Policy is risk- and jurisdiction-sensible. Many literature edges need short or delta-neutral. | **Keep no-leverage as default Mandate A.** Explicit **Mandate B** (spot long/flat/short or cash+spot only) and **Mandate C** (delta-neutral derivatives research with strict loss caps) only by human charter — not smuggled. |

### A6 — “Frozen validation methodology is sufficient for real capital”

| Challenge | Working resolution |
|-----------|-------------------|
| Gates are strong for **research integrity**. Real capital needs **shadow period, ops readiness, kill-switch drills, cost model audit**. | Do **not** weaken gates. **Add** deployment ladder layers (already sketched) as mandatory before scale. Validation methodology for **L5** is good; for **L0–L3** must be first-class in the roadmap. |

### A7 — “More programmes / more data always help”

| Challenge | Working resolution |
|-----------|-------------------|
| Phase 1 proved low-EV programmes destroy option value. | Cap science programmes; default-cancel; one structural bet or mandate pivot — not both at once without human. |

### A8 — “Autonomous RD should optimise experiment throughput”

| Challenge | Working resolution |
|-----------|-------------------|
| Throughput ≠ P(capital-ready system). | Optimise **P(end goal) / (time × capital × integrity risk)**. Cancel is success. |

### A9 — “We should climb until we find alpha”

| Challenge | Working resolution |
|-----------|-------------------|
| Infinite search is the failure mode Phase 1 stop rules addressed. | Every multi-phase plan needs **terminal C** conditions and **product fallback**. |

## 3. Two mountains (must not conflate)

| Mountain | Summit | Are we climbing it? |
|----------|--------|---------------------|
| **M1 — Capital-ready autonomous trading** | Real capital under governance with edge that survived gates + shadow | Partially: L0–L4 strong-ish; L5 weak under Mandate A free data |
| **M2 — Best-in-class research / rejection OS** | Product others (or future-you) use to not lose money on noise | **Largely yes** — and undervalued in prior “alpha-only” scoring |

**Consensus:** Both mountains are legitimate. M1 is harder and **path-dependent on mandate**. M2 is **achievable regardless of alpha** and should not be treated as failure.

A strategy that maximises P(M1) **or** delivers M2 with honest M1-stop is superior to fake M1 progress.

## 5. Multi-role debate

### Research Director
- End goal is **capital-ready system**, not Phase 2 document continuity.  
- Under Mandate A, free path is exhausted → only Path 1 (options) or Path 0 (stop).  
- If human allows Mandate C, Path 2 may **maximise P★** more than options long/flat.  
- Dual-track M2 is rational insurance.

### Scientific Reviewer
- Attacks Path 1: GEX proxy stack; P★ may be overstated.  
- Attacks Path 2: easy to fool ourselves with funding “carry” that dies on costs, liquidation, exchange risk.  
- Attacks Path 4: wrong mountain.  
- Demands **terminal stops** on every path.  
- Prefers Path 0 if data quality/price for options is poor; Path 2 only with brutal risk envelope.

### Literature Reviewer
- Mandate A free daily: prior low (matches Phase 1).  
- Options positioning: mechanism plausible; directional alpha unproven.  
- Funding/basis/carry: stronger empirical **phenomenon** literature; natural form is **not** long-only spot.  
- Conclusion: **P(edge|mandate)** may be maximised by changing mandate, not by more Mandate A free science.

### Data Reviewer
- Free historical options OI: fail.  
- Funding/OI we already have for **features**; using them as **vehicle** is policy, not data.  
- Any paid pin: snapshot time or hard veto.

### Implementation Engineer
- Stack L0–L4 is the lab’s comparative advantage.  
- Path 2 needs execution/risk work (perps, margin) — real cost.  
- Path 0/6 productisation is mostly packaging + reliability — fits frozen science core.

### Experiment Auditor
- Never weaken gates for Path 2 “because carry needs it.”  
- Shadow + tiny capital is mandatory before “autonomous manages capital.”  
- Confirmatory budget is for survivors, not fishing.

### Resolution table

| Conflict | Consensus |
|----------|-----------|
| Options Phase 2 vs rethink | **Rethink first** (this review). Options is **conditional** best under Mandate A, not automatic. |
| Mandate A vs C | **Human must choose mountain face.** Org recommends presenting both honestly. |
| α vs product OS | **Dual-track allowed**; α track has stop rules; Π track never claims edge. |
| Continue free programmes | **No.** |
| Implement now | **No.** |

## 6. Consensus: optimal programme from today

### Strategic stance

1. **Stop treating “BTC daily long/flat free discovery” as the primary mountain face.**  
2. **Declare two legitimate endgames:**  
   - **M1:** capital-ready autonomy under an **explicit mandate**  
   - **M2:** trustworthy research OS (value even if M1 fails)  
3. **Choose exactly one α-facing climb at a time:**  
   - **If mandate stays A (long/flat, no leverage vehicle):** Path **1** (options OI/gamma one-shot) **or** Path **0** (stop).  
   - **If human opens mandate for market-structure book:** Path **2** becomes the primary M1 climb (higher P★), with Path 1 deferred or cancelled.  
4. **Always maintain dual-track optionality for M2** unless human forbids.  
5. **Deployment path is first-class:** survivor → shadow → micro-capital → scale; ops readiness is not optional polish.

### Recommended default (if human wants one recommendation without yet changing mandate)

**Path 6 = Path 1 ⊕ M2 dual-track**, with Path 0 as the branch if funding is refused:

```text
Human decision fork
  ├─ Refuse paid structural data → Path 0 (C + M2 productise)
  ├─ Keep Mandate A + fund options history → Path 1 (one programme, hard stop → C or shadow)
  └─ Open Mandate C charter → Path 2 primary (funding/basis book under strict risk); do not also burn options budget until Path 2 decides
```

**Do not** pursue Path 1 and Path 2 in parallel.  
**Do not** reopen free technical/structural filler.
